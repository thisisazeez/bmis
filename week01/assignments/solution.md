## Part A: Definitions

### Program (Model Answer)

A program is a set of instructions written in a language a computer can understand and execute, designed to perform a specific task. For example, when you open a calculator app on your phone and type "5 + 3," a program receives those numbers as input, follows instructions to add them, and displays "8" as output. The key property of a program is that every instruction is followed exactly, in order -- the computer does not improvise or skip steps.

**What earns full marks:** A definition that captures "instructions," "specific language," and "input to output." An example that is concrete and clearly illustrates the definition.

**Common weak answers:** "A program is something on a computer" (too vague). "A program is code" (circular -- code is not defined either).

---

### Algorithm (Model Answer)

An algorithm is a step-by-step plan for solving a problem, written in a way that any person could follow, regardless of what programming language they know. For example, an algorithm for making instant noodles might be: (1) boil water, (2) open the noodle packet, (3) place noodles in the boiling water, (4) wait three minutes, (5) drain excess water, (6) add seasoning, (7) stir and serve. This is not code -- it is a logical sequence of steps that could later be translated into code if the task were something a computer handles.

**What earns full marks:** A definition that captures "step-by-step," "problem-solving," and "language-independent." An example that shows ordered steps.

**Common weak answers:** "An algorithm is a set of instructions" (this is also the definition of a program -- the student must distinguish the two). "An algorithm is a formula" (not quite; a formula is a single expression, an algorithm is a process).

## Part B: Written Assignment (Model Answer)

Below is an example of a response that would earn high marks. Students do not need to match this exactly -- they need to demonstrate understanding in their own words.

---

Programming is more than just sitting at a computer and typing code. It is a process that begins long before any code is written and continues after the first version of a program runs. The process starts with understanding the problem: what inputs will the program receive, and what output should it produce? Next comes designing an algorithm -- planning the logical steps needed to transform that input into the correct output. Only after the plan is clear does a programmer begin writing code, translating the algorithm into a specific programming language. But the work does not stop there. Testing checks whether the program actually produces the right output for different inputs, not just the one example tried first. And debugging -- finding and fixing errors -- is a normal, expected phase, not a sign of failure.

A good program has several characteristics beyond simply working. First, it must be correct: it should produce the right output for all valid inputs, not just the one case tested during development. Second, it should be readable. Code is read far more often than it is written, and a program with clear names and logical structure is easier to understand, grade, and fix. Third, a good program is reliable -- it handles unexpected situations without crashing. For example, the Wi-Fi algorithm from class included a step for what to do if the connection fails, rather than simply assuming success. Fourth, it should be well-documented: comments within the code should explain why decisions were made, so that another person (or the programmer's future self) can understand the reasoning later. Finally, a good program is maintainable -- it can be updated or extended without needing to be rewritten from scratch.

These characteristics matter because software is rarely finished. Programs are updated, shared, and reused. Writing code that only works once, for one input, in one person's head, is not programming -- it is a lucky accident.

**Word count:** 298

### Grading Notes

- Students who list characteristics without explaining **why** each matters should receive partial credit (roughly half marks for those criteria).
- Students who use a concrete example (toothbrushing, Wi-Fi, or their own) to illustrate a point should receive full marks for the "use of examples" criterion even if they only use one example, provided it is used meaningfully.
- A response that reads like a pasted textbook definition with no evidence of personal understanding should not receive more than 40% of the available marks.
